## 2. رؤية BAYAN

منصة معرفة وأخبار عربية/إنجليزية تقدم إجابات ومقالات قابلة للتحقق، بحثًا متعدد المصادر، أخبارًا موثقة، بيانات مباشرة، صفحات موضوعية صحيحة وتجربة هاتف ممتازة.

المبادئ الملزمة:
1. الدليل والاسترجاع والتحقق قبل التوليد.
2. مصادر متعددة مستقلة، وعدم الاعتماد على ويكيبيديا أو مزود واحد.
3. التمييز بين المعلومة الموثقة، وملخص الذكاء الاصطناعي، والاستنتاج، وعدم اليقين.
4. إذا لم تكف الأدلة، يُقال ذلك بوضوح ولا تُختلق معلومة.
5. العربية والإنجليزية مساران كاملان؛ لا رجوع صامت من الإنجليزية إلى العربية.
6. لا تُنشأ مقالة من استعلام البحث وحده.
7. أسماء المصادر والأدلة تُعرض داخل تجربة BAYAN دون إغراق الزائر بروابط خام.
8. مساهمات الزوار تخضع للمراجعة قبل النشر.
9. لا يُعلن نجاح إصلاح أو ميزة في الإنتاج إلا بعد اختبارها والتحقق من SHA المنشور.

## 6. سجل الحوادث والمشكلات

### 6.1 حصة D1 وأخطاء 5xx وCPU — أكتوبر 2026
سُجل نفاد قراءات D1 وخطأ الحصة 7500. ووردت لقطة سابقة بأرقام تقريبية: D1×252، 503×1500، CPU×218، 500×186، 502×780. هذه ليست قياسات حية الآن.

ذُكر دمج PR #490 بتاريخ 2026-10-20 لإضافة حارس لحصة D1، مع تحسينات لتقليل استعلامات الطابور. يحتاج الأمر تحققًا من الكود المنشور والسجلات بعد التغيير.

**الوقاية:** مراقبة الحصة مبكرًا، تقليل الاستعلامات المتكررة والمكلفة، استخدام دفعات محدودة وتخزين مؤقت حيث يناسب، وضع سقف لإعادة المحاولة، وعدم إجراء عمليات كتابة أثناء التشخيص. لا تحذف بيانات ولا تعدّل migration مطبقة.

### 6.2 تعطل نشر الأخبار بسبب شرط خمسة ناشرين مستقلين
سجلت لقطة تاريخية سبب منع: independent_evidence_below_threshold: publishers=1..4; required=5. ووردت لقطة أقدم فيها 1697 سجلًا في news_archive، وlinked=0، وأهلية sitemap للأخبار 0. كما ذُكر 162 مقالًا (81 عربيًا و81 إنجليزيًا)، و95 بلا صورة، و126 أقل من 2500 حرف، وخمس مجموعات عناوين مكررة. هذه أرقام تاريخية وليست حالة حية.

**قيد لا يجوز كسره:** الحفاظ على شرط خمسة ناشرين مستقلين؛ لا تخفّضه ولا تتجاوز التحقق لمجرد زيادة عدد الأخبار.

**الحل:** تتبع مرحلة التجميع والتحقق، توسيع استرجاع المصادر الموثوقة، إزالة تكرار القصة والناشر، توضيح أسباب الرفض، ثم تشغيل دورة آمنة وإثبات وجود مقالات منشورة مؤهلة. لا تساوِ بين الأرشيف والمقال المنشور.

### 6.3 محاولات التوليد ومزودو AI
ورد أن article_attempts ارتفع من 74 إلى 126 بسبب زيادة العداد قبل نجاح التوليد؛ وظهرت أخطاء OpenAI credit_balance_exhausted (429) وWorkers AI 4006. كما وردت حالات قديمة: 702 غير مجربة، و24 مؤجلة، و8 مسودات غير متحققة.

ذُكرت تغييرات: الميزانية الافتراضية 10→40، مهلة Gemini 9→18 ثانية، مهلة Workers AI 11 ثانية، وإزالة ask() إضافية من الطابور؛ تحتاج جميعها مراجعة واختبارًا حاليًا.

**ترتيب المزود المطلوب:** Gemini 2.5 Flash عبر GEMINI_MODEL (لا تستخدم latest) ثم Workers AI؛ OpenAI اختياري فقط، ولا تجعل الموقع يعتمد على رصيد OpenAI مدفوع. تحقق من صحة GEMINI_API_KEY داخل إعدادات Cloudflare دون كشف القيمة.

**الوقاية:** احتساب المحاولة عند النقطة الصحيحة، تسجيل النتيجة والخطأ، مهلات وحد للمحاولات، اختبار fallback، وعدم تسجيل الأسرار.

### 6.4 البحث يعرض «تعذر فتح الملف» ثم نتيجة وحيدة
وردت شكاوى بأن البحث يعرض «تعذر فتح الملف الآن» ثم نتائج قليلة أو ويكيبيديا، أو صفحة شخص بلا تحليل كافٍ. السبب الجذري لا يُفترض قبل تتبع الطلب من الواجهة إلى API والمزود.

**الحل:** إعادة إنتاج الاستعلام، تسجيل الطلبات وحالاتها دون أسرار، اختبارات e2e للأشخاص والعلوم والأخبار بالعربية والإنجليزية، توفير fallback متعدد المصادر، فصل فشل فتح الملف عن نقص الأدلة، وعدم توجيه الزائر لروابط خام عشوائية.

### 6.5 SEO وخرائط الموقع
وردت مؤشرات تاريخية في Search Console: 204 صفحات مكتشفة و0 مفهرسة، وخطأ سابق في news sitemap من نوع missing urlset/url ثم أهلية 0. لا تعكس هذه المؤشرات بالضرورة الوضع الحالي.

**الحل:** تحقق من HTTP وXML لكل sitemap؛ لا تُخرج news sitemap غير صالح عند عدم وجود عناصر؛ أدرج المقالات المنشورة المؤهلة فقط؛ صحح robots وcanonical وhreflang وJSON-LD؛ امنع فهرسة المسودات والصفحات الرقيقة. أعد الفحص في Search Console بعد النشر، مع العلم أن إصلاح sitemap لا يضمن الفهرسة فورًا.

### 6.6 لوحة الإدارة
ورد بلاغ بأن /admin تعرض «تعذر تحميل لوحة الإدارة». تتبع طلب API الفاشل وحالته، تحقق من الجلسة والأسرار والصلاحيات وD1، أظهر خطأ مفهومًا دون كشف معلومات، واختبر المستخدم المسجل وغير المسجل. لا تعطل الحماية لإخفاء الخطأ.

### 6.7 عدم تطابق SHA المنشور
سجل تاريخي أظهر مرة SHA متوقعًا 6659235 مقابل BAYAN_COMMIT_SHA مختلف يبدأ d5e71b0. ثم ورد نشر مرتبط بـPR #521 وSHA يبدأ a274215 وDeployment ID يبدأ cc780839 بتاريخ 2026-10-21. هذه معلومات تاريخية ولا تثبت SHA الإنتاج الحالي.

**الوقاية:** مقارنة SHA في GitHub Actions مع SHA الإنتاج عبر /.well-known/build.json أو وسيلة موثوقة، والتحقق من صفحة حقيقية بعد النشر. لا تعتمد على نجاح workflow وحده، ولا تنشر يدويًا باستخدام Wrangler.

### 6.8 الأرشيف والروابط والمحتوى الرقيق
وردت حالات لا ترتبط فيها عناصر الأرشيف بمقالات منشورة (linked=0)، وصفحات قصيرة أو بلا صور. افصل بين سجل الأرشيف والمسودة والمقال المنشور والصفحة القابلة للفهرسة. اختبر أن كل بطاقة تفتح مقالًا صحيحًا يحتوي نصًا وصورة وإسنادًا مناسبًا.

## 8. ضوابط غير قابلة للتفاوض

- لا حذف بيانات الإنتاج.
- لا تعديل migrations مطبقة؛ أي تغيير مخطط جديد يجب أن يكون migration جديدة بعد فحص التوافق.
- لا أسرار داخل الكود أو التوثيق أو issues أو السجلات.
- لا تخفيض شرط خمسة ناشرين مستقلين.
- لا صور وهمية أو غير مرتبطة بالمحتوى.
- لا خدمة مدفوعة أو ترقية Cloudflare قبل شرح التكلفة والأثر الرقمي وموافقة المالك.
- لا اعتماد افتراضي على OpenAI API مدفوع.
- لا نشر يدوي بـWrangler؛ النشر عبر GitHub Actions المعتمد.
- لا تجاوز CI ولا دمج إصلاح بلا اختبارات مناسبة.
- تغييرات صغيرة ومعزولة وPR واضح.
- BAYAN AI للقراءة والتشخيص افتراضيًا؛ أي إجراء مؤثر يحتاج موافقة صريحة وسجل تدقيق.
- لا تعتبر إنشاء ملف أو نجاح build إثباتًا لعمل الميزة في الإنتاج.
- لا تضع بيانات شخصية أو أسرارًا أو نسخًا كاملة من قاعدة البيانات في المستودع.

## 9. طريقة العمل القياسية للإصلاح

1. إعادة إنتاج المشكلة وتسجيل المسار واللغة والاستعلام والوقت.
2. تتبع الواجهة → API → المزود/الاسترجاع → D1/Worker، مع تنقيح الأسرار.
3. تسجيل SHA الحالي واختبار فاشل يثبت المشكلة وخط أساس.
4. تنفيذ أصغر تغيير يعالج السبب الجذري.
5. تشغيل npm run check والاختبارات المناسبة للوحدة والتكامل وe2e.
6. مراجعة الأمن والتكلفة والحصص وإعادة المحاولة وخطة التراجع.
