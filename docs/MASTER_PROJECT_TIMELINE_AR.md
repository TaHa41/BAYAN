## 1. كيف نقرأ الحالات

- **دليل GitHub:** يظهر commit أو PR أو ملف في المستودع.
- **دمج مؤكد:** يوجد commit دمج معروف أو يظهر PR مدمجًا من GitHub.
- **اختبار مؤكد:** نتيجة اختبار أو CI واضحة مرتبطة بالـSHA المعني.
- **إنتاج مؤكد:** SHA الإنتاج أو اختبار مباشر يثبت السلوك بعد النشر.
- **غير محسوم:** لدينا بلاغ أو وصف إصلاح، لكن دليل النجاح النهائي غير متاح في هذا السجل.

لا توجد عبارة «تم الإصلاح نهائيًا» إلا إذا تحقق الشرطان: اختبار مناسب + تحقق إنتاجي مرتبط بالـSHA.

## 2. الخط الزمني

### 2026-10-02 — تأسيس المشروع
- بدأ طلب بناء BAYAN من الصفر كمشروع مستقل، مع المحافظة على مواصفات المنتج.
- ظهرت بداية Worker وTypeScript وWrangler واختبارات Vitest وCI وملفات الإعداد الأساسية وفق سجل العمل.
- **قيد تاريخي:** ذُكر حينها أن النشر وصحة الإنتاج لم يكونا قد تأكدا بعد. لا نستخدم وجود الملفات وحده لإثبات نجاح الإنتاج.

### 2026-10-04 — البنية والمهندس ذاتي الإصلاح
- وُصفت بنية Cloudflare Workers + TypeScript + Assets + D1 + Workers AI/AI Gateway + AI Search + GitHub Actions/Guardian + Telegram + PWA، مع العربية والإنجليزية.
- الهدف التشغيلي: اكتشاف المشكلة → تحديد السبب بالدليل → إصلاح محدود → اختبارات → CI → نشر آلي → تحقق إنتاجي → Guardian → إغلاق أو تراجع آمن.
- يجب الفصل بين إصلاحات آلية قابلة للعكس وبين تغييرات الأمان أو البيانات التي تتطلب موافقة بشرية.
- وردت مراجع إنتاج تاريخية مثل `b010e330…` و`4d370a670434628906683e6a5ad9021ec363e645` و`bedb6f6c41222ce6a30e6d77ef40b4ff7f65adad` في تقارير سابقة؛ يلزم ربط كل منها بسجل نشر موثوق قبل الاستناد إليها كحالة حالية.

### 2026-10-05 إلى 2026-10-06 — تدقيق المستودع وGuardian
- سُجل أن مراجعة سابقة لم تشمل كل ملفات `main`، وأن عملًا سابقًا وقع على `v1` بدلًا من الفرع المطلوب؛ وهذا سبب لإلزامنا بتحديد الفرع والـSHA قبل أي تعديل.
- ورد جرد تاريخي شمل migrations وworkflows وscripts وواجهة واختبارات ووثائق وD1 وAI/AI Search وCron وObservability.
- ذُكر أن مسار نشر CI→D1→Cloudflare→Smoke→Guardian نجح في نقطة زمنية معينة، لكن إصلاح أخطاء الكود تلقائيًا وإعادة النشر والتراجع لم يكن مكتملًا في ذلك التقرير.
- **منع التكرار:** لا نعلن اكتمال التدقيق دون تعداد الملفات والفروع ونتائج Actions، ولا نخلط بين حالة فرع تجريبي وحالة `main`.

### 2026-10-09 — البحث والصور والمصادر

- **الوقاية:** لا تخفِ أخطاء المزود؛ سجّل سبب الفشل دون أسرار، واختبر صور النتائج ومصادرها، ولا تجعل ويكيبيديا أو مزودًا منفردًا نهاية البحث.

### 2026-10-17 إلى 2026-10-20 — استقرار D1 والأخبار

- ذُكر نمو الأرشيف، لكن عدد عناصر الأرشيف لا يساوي عدد المقالات المنشورة أو المؤهلة لخريطة الأخبار.

## 3. متطلبات المستخدم التي يجب أن تبقى ضمن المرجع

### المنتج والمحتوى
- واجهة عربية/إنجليزية كاملة: `?lang=ar` باتجاه RTL و`?lang=en` باتجاه LTR، مع منع الرجوع الصامت بين اللغتين.
- البحث و«اسأل بيان» يجب أن يعرضا نتائج مرتبطة بالسؤال من أكثر من مصدر، مع تمييز الدليل والملخص والاستنتاج وعدم اليقين.
- لا إنشاء مقالة من مجرد استعلام؛ ولا نصوص سيرة ذاتية مختلقة أو صور لا علاقة لها بالموضوع.
- التوجيه الصحيح للأقسام، وخاصة الأشخاص والرياضة؛ الحفاظ على المسارات القديمة `news` و`prices`.
- الأقسام المطلوبة تشمل العلوم، التقنية، الاقتصاد، السياسة، الصحة، التاريخ، الأشخاص، الرياضة، السفر، الفن، الأخبار الموثقة، الاتجاهات، الأسعار/البيانات المباشرة، ومسارات arab/egypt/world بتسمياتها المعتمدة.
- شرط الصورة أساسي للمقال المنشور: الأصل إن أمكن، وإلا صورة مرتبطة فعلًا بالشخص/الموضوع أو توضيح واضح لتعذر صورة مناسبة؛ لا تزيل شرط الصورة للمقالات الموثقة في الخريطة الاحتياطية.
- تجربة هاتف أولًا، قائمة جانبية، الوضع الداكن/الفاتح/التلقائي، معاينات مشاركة سليمة، وأرشيف وروابط داخلية صحيحة.
- دعم بيانات الطقس ومواقيت الصلاة والأسعار في مسارات منفصلة حسب نوع البيانات.

### الإدارة والأمان والتشغيل
- BAYAN AI للتشخيص أولًا وبصلاحية قراءة افتراضية؛ موافقة قبل الإجراءات المؤثرة، مع سجل تدقيق.
- لا حذف بيانات، ولا تعديل migration مطبقة، ولا أسرار في الكود أو التقارير، ولا تخفيف شرط خمسة ناشرين مستقلين.
- لا ترقية مدفوعة في Cloudflare قبل بيان أثر رقمي، ولا رصيد OpenAI مدفوع؛ لا نشر يدوي باستخدام Wrangler.
- إصلاح ذاتي آمن فقط: كشف السبب بالدليل، patch محدود، اختبار، CI، نشر آلي، تحقق إنتاجي، Guardian، وإغلاق أو rollback مع إشعار.
- GA4: `G-Y16MK39Q6X` وفق السجل؛ المطلوب استبعاد زيارات المالك والاختبارات حيثما أمكن والتحقق من إعداد ذلك.
- Telegram قناة التنبيه المذكورة في سجل المشروع؛ Resend لم يكن مطلوبًا بعد فشل الإعداد سابقًا.

## 4. قائمة الأدوات المطلوبة — لا تخلط الطلب بالاتصال الفعلي
Playwright CLI، Playwright MCP و`.mcp.json`، Supabase فقط عند وجود ضرورة مثبتة دون نقل D1 تلقائيًا، Strix في بيئة اختبار آمنة، Skill UI (يحتاج تحديد النطاق قبل الدمج)، Context7، Graphify لرسم معرفة المستودع، OmniRoute بشرط ألا يضر الأداء، Cloudflare AI Search باسم `bayan-search`، ScrapeGraphAI بعد فحص المفتاح والتكلفة، Scrapling MCP، Agent Reach، Lighthouse/PageSpeed، `integrations-check.yml`، `lighthouse-audit.yml`، Gemini 2.5 Flash ثم Workers AI كبديل، OpenAI اختياري فقط، وأدوات صور/فيديو مجانية للتسويق بلا وجه. لكل أداة يجب تسجيل: هل الملف موجود؟ هل الاتصال قائم؟ هل نجح اختبار فعلي؟ ما التكلفة والصلاحيات؟ وما الدليل؟

## 5. بوابة منع تكرار المشكلة

قبل أي إصلاح:
1. سجل البلاغ كما ظهر، اللغة، المسار، الاستعلام، الوقت، والأثر.
2. حدد الفرع والـSHA الفعليين؛ افحص `main` لا فرعًا جانبيًا بالخطأ.
3. أعد إنتاج المشكلة واكتب اختبارًا يفشل قبل الإصلاح.
4. تتبع السبب من الواجهة إلى API ومزود الخدمة وقاعدة البيانات.
5. أصغر تغيير آمن، دون بيانات إنتاج أو أسرار أو migration مطبقة.
6. شغّل اختبارات المشروع وCI، واحفظ الروابط والنتائج.
7. بعد الدمج، تحقق من SHA المنشور عبر علامة build موثوقة.
8. اختبر الوظيفة الحقيقية في الإنتاج وسجل الاستجابة والنتيجة.
9. راقب آثارًا جانبية على البحث والأخبار والصور والفهرسة واللغتين.
10. لا تغلق البند إن تعذر التحقق؛ سجّل العائق والخطوة التالية والجهة المطلوبة.

## 6. فجوات لا يجوز إخفاؤها

- لم يتم في هذه المراجعة إثبات أن كل commits منذ بداية المشروع قد قُرئت واحدًا واحدًا؛ هذا يتطلب تصدير/تصفح كامل للسجل مع pagination، ومراجعة PRs وActions.
- لا يوجد في هذه الوثيقة إثبات حي أن أول مقال أخبار مؤهل منشور أو أن news sitemap يحتوي روابط منشورة الآن.
- لا يوجد إثبات أن كل أداة مطلوبة متصلة أو أن Lighthouse/Playwright/MCP اجتازت التشغيل الفعلي.
- حالة `/admin`، واستبعاد زيارات المالك من GA4، وصلاحية Gemini الحالية، وحصص D1/Workers الحالية، وفهرسة Google الحالية تحتاج أدلة حديثة.
- لا تُعد هذه الفجوات نجاحًا أو فشلًا نهائيًا؛ إنها أعمال تحقق مفتوحة، ويجب تحديثها عند توافر الأدلة.
