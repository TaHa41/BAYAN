# BAYAN v2 — إعادة البناء من الصفر

**الحالة:** أساس معماري فقط. لا يُدمج في `main` ولا يُنشر قبل اكتمال قائمة التكافؤ أدناه.
`main` ينشر تلقائيًا على الموقع الحي، لذلك يُبنى v2 في مجلد منفصل ويُحذف الكود القديم في PR التحويل فقط (يبقى في تاريخ git).

## ما علّمنا إياه الكود القديم (قواعد ثابتة في v2)
1. **الأدلة:** "موثّق" يتطلب 5 ناشرين مستقلين على نطاقات HTTPS مختلفة؛ المجمّعات (Google News وMSN…) والنسخ المكررة لا تُحسب. (`src/evidence.ts`)
2. **البحث لا ينهار:** كل مزود معزول بمهلة وإعادة محاولة، وفشل مزود لا يُفشل البحث، وعند عدم وجود نتائج نقول ذلك مع سبب كل مزود بدل اختلاق نتيجة. (`src/search.ts`)
3. **لا نجاح بلا دليل:** حالة "تم الإصلاح/النشر" لا تُعلن إلا بتحقق فعلي.
4. **تدهور آمن:** فشل التخزين لا يُسقط الصفحة (مثال: sitemap يعود صالحًا ومعه `x-bayan-degraded`).
5. **الإعلانات:** `/ads.txt` من متغير `ADS_TXT` فقط، ولا يُخترع معرّف ناشر.
6. **قيود لا تُمس:** لا حذف بيانات D1، لا تعديل migrations مطبقة، لا لمس الأسرار، لا مزودون مدفوعون تلقائيًا.

## قائمة التكافؤ قبل التحويل (كل بند: كود + اختبار + دليل إنتاج)
- [ ] مزودو البحث (Wikipedia/Wikidata، GDELT، RSS، Workers AI، Gemini) خلف واجهة `Provider`
- [ ] تخزين D1 خلف واجهة (المقالات، الأرشيف، البحث، التحليلات) على نفس قاعدة البيانات الحالية
- [ ] دورة الأخبار (جمع ← تحقق ← مسودة ← نشر) مع منع التكرار وحد ميزانية AI
- [ ] صفحات: الرئيسية، الأقسام، المقال، الشخص (مقال كامل + صورة مرخّصة)، البحث
- [ ] الأسعار الحية، الطقس، مواقيت الصلاة لأي مدينة/دولة، حكمة متغيرة
- [ ] لوحة الإدارة + الإحصائيات (بدون زيارات المالك والإدارة والذكاء الاصطناعي)
- [ ] SEO: canonical وhreflang وJSON-LD وخرائط الموقع وصورة المشاركة PNG
- [ ] جاهزية الإعلانات (حاويات بحجم ثابت، ads.txt)
- [ ] ثنائية اللغة RTL/LTR على الهاتف، وإمكانية الوصول
- [ ] مسار نشر آمن + تراجع، وفحص SHA بعد النشر

## الخطوة التالية المقترحة
ربط `Provider` الأول (Wikipedia/Wikidata) وتخزين D1 للقراءة فقط، ثم صفحة المقال، كل واحدة في PR صغير.
